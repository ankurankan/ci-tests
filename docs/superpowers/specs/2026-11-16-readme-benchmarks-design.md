# README rewrite and performance comparison — short design

Date: 2026-11-16 · Status: approved by the owner in conversation · Branch: `feature/readme-benchmarks`
(off `feature/rename-fastcit`, which renames every package to `fastcit`)

## Intent

Make the root README short and easy to read for users who install the released packages, and show how
FastCIT performs against the other conditional-independence (CI) test packages.

## Decisions (owner)

- Write the root README in **ASD-STE100 Simplified Technical English**.
- Remove the per-test details. "Available tests" is a table with **two columns: test name, supported data
  type**.
- Install instructions assume the packages are released: `pip install fastcit`, `npm install fastcit`,
  `install.packages("fastcit")`, `cargo add fastcit-core`.
- Fewer examples, one short example per language, shown only for the language the reader chooses.
- Add a performance comparison with other packages. Compare against pgmpy **`dev` branch at commit
  `a67c17d9`** (not `feature/optimization`).

## Approaches

- Language "tabs": GitHub Markdown has no tabs. Chosen: one collapsible `<details>` block per language
  (Python, R, JavaScript, Rust), all collapsed, so the reader opens only the language they use. Rejected: a
  separate docs site with real tabs (out of scope).
- pgmpy reference: chosen `dev` (owner). Rejected: release 1.1.2 (no HSIC/KCI), `feature/optimization`.
- Numbers: chosen a committed, re-runnable benchmark (`benchmarks/`) whose summary the README quotes.
  Rejected: quoting earlier ad-hoc scratchpad runs (not reproducible, mixed machine load).

## Design

### `benchmarks/` (new, committed)

- `benchmarks/data.py`: seeded synthetic datasets, no downloads. Discrete: 30 variables, 2–4 levels, random
  DAG with random conditional tables, n = 10 000. Gaussian: 30 variables, linear SEM, n = 10 000. Nonlinear:
  8 variables (tanh/sin/square links), n = 300 and 1 000. Mixed: 3 categorical + 3 continuous, n = 2 000.
- `benchmarks/queries.py` (or inside `data.py`): seeded, de-duplicated queries — discrete 50 (|Z| 0–3),
  Gaussian 50 (|Z| 0–4), HSIC all pairs at n = 300, KCI 30 at n = 300 and 10 at n = 1 000, GCM 50
  (Gaussian), Pillai 40 (mixed, |Z| 0–2). Written to one JSON file both language scripts read.
- `benchmarks/bench_python.py`: FastCIT vs pgmpy `dev` (a67c17d9) vs causal-learn vs andrey-core.
  `benchmarks/bench_r.R`: FastCIT (R) vs pcalg vs bnlearn vs dHSIC. Same test mapping as the earlier
  cross-package comparison: χ² and G² (no Yates, so every package computes the same statistic), Fisher-z,
  Pearson t, HSIC, KCI, GCM (pgmpy default), Pillai (pgmpy default = random forest; FastCIT = linear — the
  README states that these differ).
- Timing method: for each engine, 3 passes; each pass builds new test objects (not timed; caches off where
  an option exists); each query timed once per pass; per-query best of 3; report the median in ms.
- Agreement: for each package and test, the largest |Δp| against FastCIT where the definitions match;
  written to the results (not the README).
- Outputs: `benchmarks/results/python.json`, `benchmarks/results/r.json`, and `benchmarks/results/summary.md`
  (tables generated by a small script, with date, CPU, OS, package versions and commit hashes).
- `benchmarks/README.md` (STE): what is measured, how to install the comparison packages (including
  `pip install git+https://github.com/pgmpy/pgmpy.git@a67c17d9`), how to run, how to read the tables.

### Root `README.md` (rewritten, STE)

Sections: title and tagline · one short paragraph on what FastCIT is · Install (four commands) · Quick
start (four collapsed `<details>` blocks, one short example each) · Available tests (two-column table: test,
data type) · Performance (two small tables — Python packages, R packages — median ms per test call, with
machine and version note, link to `benchmarks/`) · Documentation and contributing links · License.
STE rules applied: short sentences (≤ 20 words for instructions, ≤ 25 for descriptions), active voice,
imperative for instructions, one instruction per sentence, simple approved words, no idioms.

## Non-goals

- Binding READMEs (`crates/*/README.md`) and API docs stay as they are.
- No end-to-end PC benchmark in the README (per-call numbers only; the benchmark README may mention PC).
- No changes to the library code.
